# Local persistence server audit — integration handoff

Scope: `server.mjs` at base commit [`aef1a74`](https://github.com/snapquast73-boop/LIVPBP/blob/aef1a74c40143a7fff9d24853418002e008b79b1/server.mjs), inspected in full. This is a code and targeted behavioral review, not verification of baseball data, original-project parity, browser CORS, or a live Pages deployment. The optional Node server is separate from GitHub Pages, which publishes static content ([GitHub documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)).

## Findings

- **Unhandled malformed URL — confirmed.** The request handler calls `decodeURIComponent(pathname)` without a catch (line 396). In an isolated copy of the server, a GET for `/%ZZ` disconnected the client and exited the Node process with code 1. `decodeURIComponent` throws on malformed sequences ([ECMAScript specification](https://tc39.es/ecma262/multipage/global-object.html#sec-decodeuricomponent-encodeduricomponent)). Integration request: catch malformed paths and return 400; add a regression test.
- **Persistence key collision — confirmed.** At line 106, `review.id || review.atBatIndex || ''` treats the valid numeric index `0` like a missing index. In an isolated server copy, POSTing two entries for the same game, one with `atBatIndex: 0` and one with no ID or index, then POSTing an empty list yielded one entry instead of two. The merger also ignores other properties as keys, so additional same-at-bat distinct entries without IDs may collide. Integration request: review the client identity contract; do not silently collapse unidentified records. Use nullish checks for zero and flag records lacking a reliable identity.
- **Unrestricted local-server write access — code inspection.** Server binds `0.0.0.0` (line 23), allows all origins (lines 51–53, 255–262), and accepts unauthenticated POSTs (346–365). Any network client reaching the port may write up to the configured size limit to the feed log. This does not describe the static Pages host. Integration request: do not recommend exposing this optional server publicly without access controls; flag it for review. Node's [`server.listen`](https://nodejs.org/api/net.html#serverlistenport-host-backlog-callback) documentation describes binding behavior.
- **Static directory exposure — code inspection.** Static GET/HEAD serves files under the repository root (lines 390–441), including dotfiles if present; symlinks are followed by `fs.stat`. Thus a local checkout can expose `.git` and other local files, and symlinks may point outside the intended directory. This is a local Node server concern, not a claim about Pages. Node documents [`fs.stat`](https://nodejs.org/api/fs.html#fsstatpath-options-callback) and its behavior on symlinks. Integration request: restrict served paths, deny dotfiles and validate resolved real paths before recommending public use.
